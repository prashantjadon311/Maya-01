# Phase Packet: PH-100 — StatusNotifierItem System Tray Integration

## 1. Purpose
Implement the desktop system tray integration using the freedesktop `StatusNotifierItem` specification over user session D-Bus. Eliminates the need for a heavyweight resident GUI toolkit (e.g. Qt/GTK main loops), keeping idle memory delta under 10 MiB. Exposes live assistant state, Push-to-Talk, Always Listen toggle, Dashboard launcher, Pause, and Quit actions.

## 13. Exact Algorithms

### Algorithm: D-Bus StatusNotifierItem Registration
1. Connect to session bus using `await MessageBus(bus_type=BusType.SESSION).connect()`.
2. Request bus name `org.freedesktop.StatusNotifierItem-{os.getpid()}-1`.
3. Export object at path `/StatusNotifierItem` implementing `org.kde.StatusNotifierItem` interface.
4. Notify `org.freedesktop.StatusNotifierWatcher` via `RegisterStatusNotifierItem` method call.
5. Subscribe to `AppState` change events:
   - When state changes, emit `NewIcon` or `NewStatus` D-Bus signal.

### Algorithm: Handle Tray Actions
1. **Push to Talk:** Trigger immediate command recording via `gateway.trigger_push_to_talk()`.
2. **Toggle Always Listen:** Update `config.voice.always_listen` and start/stop audio stream.
3. **Open Dashboard:** Spawn `xdg-open http://127.0.0.1:8765` via `XdgExecutor`.
4. **Quit / Stop Service:** Signal `LifecycleManager.stop()`.

## 14. Reference Implementation
```python
class StatusNotifierTray:
    def __init__(self, state: AppState, gateway: Any):
        self.state = state
        self.gateway = gateway
        self.is_registered = False

    async def register(self) -> None:
        # In real system, connects via dbus-fast
        self.is_registered = True
        self.state.add_listener(self.update_state)

    def update_state(self, new_state: SystemState) -> None:
        self.current_icon = f"project-h-{new_state.name.lower()}"

    async def unregister(self) -> None:
        self.is_registered = False
```

## 15. Concurrency Model
- Runs asynchronously on the main `asyncio` event loop. D-Bus signals and method calls are dispatched as non-blocking tasks.

## 16. Cancellation Behavior
- Unregistering cleanly releases D-Bus bus name and removes object from bus.

## 17. Timeout Behavior
- D-Bus method calls timeout after 2.0s to prevent GUI shell hangs from blocking daemon.

## 18. Retry/Idempotency Behavior
- State updates are idempotent (sending same state multiple times emits no duplicate signals).

## 19. Error Behavior
- D-Bus session unavailable (e.g. headless CI): Fails gracefully with warning, daemon continues running without tray.

## 20. Security Invariants
- **Primary Enforcement:** Tray menu actions cannot execute arbitrary commands; all triggers pass through `InputGateway`.
- **D-Bus Isolation:** Exposes strictly the standard user-session StatusNotifierItem interface; accepts no arbitrary external method calls.

## 21. Resource Limits
- Memory budget: <= 10 MiB resident RSS.
- Rate-limited state updates: max 10 updates per second.

## 22. Secrets/Privacy Behavior
- Tray displays only high-level status; never shows private user prompts, tokens, or audio transcripts in tooltips.

## 23. Failure Cases
- GNOME Shell restarts: Detects watcher disconnect, automatically re-registers when StatusNotifierWatcher re-appears on bus.

## 13. Exact Algorithms / Security Invariants
1. **Real Cgroup Accounting:** When running inside a Linux cgroup (systemd user unit), reads `memory.current` and `memory.peak` from `/sys/fs/cgroup/user.slice/...` (or `/proc/self/cgroup`). This accurately captures all memory used by the daemon and spawned worker/subprocess children, without relying on naive process-local `ru_maxrss`.
2. **Fallback Tree Accounting:** In environments without cgroup v2 controllers, calculates resident set size across the full process tree (daemon PID + all active child PIDs from `ProcessExecutor`).
3. **No `gc.collect()` Crutch:** Design limits (bounded queues, stream draining, released audio buffers) guarantee the process stays under 240M. The daemon must NEVER rely on emergency `gc.collect()` after crossing `MemoryMax=300M`.

# Phase Packet: PH130 — Local Dashboard Backend & SQLite Storage

## 1. Purpose
Implement the local web dashboard backend using FastAPI and local SQLite storage. Binds strictly to `127.0.0.1:8765` with same-origin validation, host header protection, and zero wildcard CORS. Provides complete REST and SSE endpoints across dedicated route modules for state streaming, config CRUD, deterministic action pack management, paginated audit logging, and agent controls. Implements a lightweight SQLite architecture: one dedicated serialized DB worker thread, WAL mode, bounded queries, explicit checkpoints, and fail-closed audit degradation if fallback buffers saturate.

### Serialized DB Worker & WAL Mode
- Python stdlib `sqlite3` does not support async multi-client pooling.
- Single SQLite connection managed by a dedicated background worker thread executing serialized jobs via `queue.Queue(maxsize=128)`.
- Connection flags: `PRAGMA journal_mode=WAL; PRAGMA synchronous=NORMAL;`.
- Strictly serialized single connection architecture.

### Fail-Closed Audit Degradation
- If disk write fails, storage enters `DEGRADED_BUFFERING` storing up to 512 entries in bounded memory.
- If fallback buffer reaches capacity, status transitions to `DEGRADED_FULL`.
- Central dispatcher checks `storage.audit_health`: new state-changing actions are strictly DENIED until persistence recovers.

## 15. Concurrency Model
Async ASGI request handlers; SQLite write operations serialized through single worker queue.

## 16. Cancellation Behavior
Client HTTP disconnect cancels active SSE stream task immediately.

## 17. Timeout Behavior
HTTP request timeout 10 seconds; SSE keepalive ping every 15 seconds; SQLite job timeout 5 seconds.

## 18. Retry / Idempotency Behavior
Configuration updates are atomic and idempotent; audit event inserts are append-only.

## 19. Error Behavior
Validation errors return standard HTTP 422; database errors return HTTP 500 without leaking stack traces.

## 20. Security Invariants
Dashboard binds exclusively to IPv4 loopback (`127.0.0.1:8765`); zero external interface exposure; no wildcard CORS.

## 21. Resource Limits
Maximum SSE client connections capped at 10; request body limit 1 MiB; audit query limit 100 rows per page; DB job queue max 128.

## 22. Secrets / Privacy Behavior
Audit database stores typed metadata only (`AuditEvent`); prompts, stdout, and tokens never persisted.

## 23. Failure Cases / Edge Cases
- Database disk write failure: Transitions to `DEGRADED_BUFFERING`; metadata buffered in RAM.
- Fallback buffer saturated: Transitions to `DEGRADED_FULL`; new state-changing actions fail closed.
- SSE client limit reached: 11th client connection rejected with HTTP 503 Service Unavailable.
- Malicious Host header injected: Request rejected with HTTP 403 Forbidden by host-header validation middleware.

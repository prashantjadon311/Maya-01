# Phase Packet: PH-130 — Local Dashboard Backend & SQLite Storage

## 1. Purpose
Implement the local web dashboard backend using FastAPI and local SQLite storage. Binds strictly to `127.0.0.1:8443` with same-origin validation, host header protection, and zero wildcard CORS. Provides complete REST and SSE endpoints across dedicated route modules for state streaming, config CRUD, deterministic action pack management, paginated audit logging, and agent controls. Implements a lightweight SQLite architecture: one dedicated serialized DB worker thread, WAL mode, bounded queries, explicit checkpoints, and in-memory audit metadata preservation if storage degrades.

## 12. SQLite Architecture & Storage Degradation
1. **Lightweight Serialized Worker:** Python stdlib `sqlite3` does not provide an async connection pool. We freeze one clean pattern: a single connection managed by a dedicated background worker thread executing serialized queries via `queue.Queue`.
2. **WAL Mode:** Enabled on connection: `PRAGMA journal_mode=WAL; PRAGMA synchronous=NORMAL;`.
3. **Storage Degradation Strategy:** If database writes encounter disk errors (e.g. read-only filesystem, I/O error), the system transitions to `degraded=True` and accumulates audit events in a bounded in-memory deque (`maxlen=512`). State-changing audit records are preserved without crashing the daemon.
4. **Localhost & Host Header Protection:** Binds strictly to `127.0.0.1`. Middleware verifies `Host` header is `127.0.0.1:{port}` or `localhost:{port}`, rejecting DNS rebinding and wildcard CORS.

# Phase Packet: PH150 — Developer Workflows & VS Code Integration

## 1. Purpose
Implement developer workflows for Maya: repository registration, Git status and diff inspection, test command execution under policy, and launching workspaces in VS Code. Introduces the `DeveloperWorkflowService` positioned **above the central ActionDispatcher**, guaranteeing that developer tooling never bypasses policy or directly invokes executors with raw argv. Enforces that code edits require an inspection and verification loop, and that **auto-commit is strictly disabled by default**.

## 12. Internal Schemas
```
DeveloperWorkflowService
  │
  ├── Git / Test Subprocess Request:
  │     ActionRequest(tool="process.run", arguments={"argv": ["git", "status"], "cwd": repo_path})
  │     └──> dispatcher.dispatch_request() ──> PolicyEngine ──> ProcessExecutor
  │
  ├── File Edit / Read Request:
  │     ActionRequest(tool="file.read" / "file.write", arguments={"path": ...})
  │     └──> dispatcher.dispatch_request() ──> PolicyEngine ──> FileExecutor
  │
  └── Deterministic Action:
        RegistryMatch(action_id=..., slots=...)
        └──> dispatcher.dispatch_match() ──> ActionDispatcher
```

### Safety Invariants
1. **NEVER DIRECTLY INVOKE EXECUTORS:** The developer service never calls `ProcessExecutor.execute(argv, ...)` directly.
2. **NEVER FABRICATE POLICYEVALUATION:** The developer service never constructs fake `PolicyEvaluation` objects to circumvent policy checks.
3. **USE CONFIG.FILES.ROOTS:** Allowed workspace roots are validated against `config.files.roots`. There is no nonexistent `config.security.allowed_roots`.
4. **AUTO-COMMIT DISABLED BY DEFAULT:** Auto-commit is disabled by default; committing requires an explicit verification step and user confirmation.

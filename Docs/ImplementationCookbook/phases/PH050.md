# Phase Packet: PH-050 — Interactive Approval Broker & Native Popup

## 1. Purpose
Implement the `ApprovalBroker` to handle sensitive action authorization requests (`PolicyDecision.ASK_USER`). Guarantees that any action requiring user confirmation is paused until explicitly approved via an independent native popup, cryptographically bound to an immutable SHA-256 payload hash, single-use, and automatically invalidated on timeout or daemon restart.

## 12. Internal Schemas
```python
class ApprovalGrant(BaseModel):
    model_config = ConfigDict(strict=True, extra="forbid")
    grant_id: str
    action_hash: str
    created_at: float
    expires_at: float
    risk: RiskLevel
    status: Literal["PENDING", "GRANTED", "CONSUMED", "EXPIRED", "DENIED"]
```

## 13. Exact Algorithms

### Algorithm: Request Approval
1. Calculate `action_hash = hashlib.sha256(req.model_dump_json().encode('utf-8')).hexdigest()`.
2. Generate `grant_id = str(uuid.uuid4())`.
3. Check `len(self._pending_grants)`; if `>= 10`, remove the item with the oldest `created_at`.
4. Construct `ApprovalGrant` with `status="PENDING"` and `expires_at = time.monotonic() + 60.0`.
5. Insert into `self._pending_grants` under `asyncio.Lock`.
6. Dispatch popup subprocess or notify registered callback.
7. Return `grant`.

### Algorithm: Verify & Consume Grant
1. Acquire `asyncio.Lock`.
2. Lookup `grant = self._pending_grants.get(grant_id)`.
3. If not found or `grant.status != "PENDING"`, return `False`.
4. If `time.monotonic() > grant.expires_at`, set `grant.status = "EXPIRED"`, return `False`.
5. Verify `hmac.compare_digest(grant.action_hash, action_hash)`. If mismatch, return `False`.
6. Atomically delete `grant_id` from `self._pending_grants`. Set `grant.status = "CONSUMED"`. Return `True`.

## 15. Concurrency Model
- State mutation of `_pending_grants` is synchronized via `asyncio.Lock`.
- Non-blocking `asyncio.sleep` used for timeout tracking.

## 16. Cancellation Behavior
- If the calling task is cancelled while awaiting user approval, the broker cancels the popup subprocess and purges the pending grant from memory.

## 17. Timeout Behavior
- Hard timeout of `60.0s`. If no user decision is registered before expiry, the grant resolves strictly to `EXPIRED` and the action fails closed (`DENY`).

## 18. Retry/Idempotency Behavior
- `consume_grant` is strictly **non-idempotent** (returns `True` first time, `False` on any replay).
- Approval requests are never automatically retried.

## 19. Error Behavior
- Any popup failure, missing backend, or timeout raises `ApprovalDeniedError` or `ApprovalTimeoutError`.
- System resolves to DENY; executor is never called.

## 20. Security Invariants
- **Primary Enforcement:** `ApprovalBroker.consume_grant` requires exact match of `SHA-256(canonical_json(req))` and deletes token.
- **Defense in Depth:** `ActionDispatcher` verifies token status immediately before calling executor.
- **Fail-Closed:** Missing grant, expired grant, or hash mismatch strictly aborts execution.

## 21. Resource Limits
- Maximum 10 pending grants in memory simultaneously. Oldest purged if ceiling exceeded.
- Memory consumption: < 100 KB total.

## 22. Secrets/Privacy Behavior
- Approval grants and action hashes are held purely in volatile RAM. Never written to disk or logged in plaintext.

## 23. Failure Cases
- Popup process fails to launch: Fails closed to DENY.
- User closes popup window without selecting Allow: Treated as DENY.
- System crashes while dialog is visible: On reboot, memory is empty; execution does not proceed.

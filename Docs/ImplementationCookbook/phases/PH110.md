# Phase Packet: PH-110 — Firefox WebExtension & Native Messaging Host

## 1. Purpose
Implement the multi-tier browser automation bridge separating the resident daemon, transient native host executable, and Firefox WebExtension. The daemon exposes an authenticated Unix Domain Socket (UDS) under `XDG_RUNTIME_DIR` (mode `0600`) with `SO_PEERCRED` UID verification. The transient native messaging host is spawned by Firefox (`browser.runtime.connectNative`), bridges stdin/stdout to the daemon UDS with 4-byte native framing, and forwards only typed bounded messages. Every command enforces a strict 4-fold check (daemon allowlist + domain capability + Firefox permission + origin recheck) with sensitive element restriction.

## 12. Security Boundaries & Architecture

```
Daemon (resident)
  ↕ Authenticated UDS (mode 0600 under XDG_RUNTIME_DIR, SO_PEERCRED UID check, session nonce)
Transient Native Host (project_h_native_host.py)
  ↕ Standard Firefox Native Messaging (stdin/stdout with 4-byte native length header)
Firefox Extension (background.js / content scripts)
```

### 4-Fold Permission Gating
Every browser action must pass:
1. **Daemon Domain Allowlist:** Sourced from `config.browser.allowed_domains`.
2. **Exact Domain Capability:** Action type permitted for domain (e.g. read vs click).
3. **Firefox Extension Host Permission:** Declared in `manifest.json`.
4. **Immediate Current-Origin Recheck:** Content script verifies `window.location.origin` immediately prior to DOM query or execution.
5. **Sensitive Element Restriction:** Password inputs, hidden auth tokens, and session cookies are hard-blocked from read or type actions.

### Framing & Size Bounds
- Length framing: 4-byte native-endian unsigned integer.
- Max message size: 1 MiB Project H limit (applies to daemon UDS and native messaging bridge).

# Phase Packet: PH080 — Local Voice Wake Pipeline

## 1. Purpose
Implement the local-first voice wake detection pipeline. Continuous microphone sampling is confined entirely to a local in-memory circular ring buffer. Pre-wake audio is processed on-device by a single-threaded `openWakeWord` engine with **zero outbound network connectivity**. Post-wake command recording is initiated strictly after wake confirmation, producing a clean post-wake audio segment terminated by VAD silence or configured timeout. Pre-wake ring buffer audio is NEVER prepended to command audio sent to cloud STT.

## 12. Internal Schemas
1. **ZERO NETWORK BEFORE WAKE:** Audio capture and wake processing use zero network sockets. Audio frames stay entirely in local RAM.
2. **NO PRE-WAKE PREPEND:** Pre-wake ring buffer data is wake-detector-only. Under NO circumstances is pre-wake audio prepended to command audio sent to cloud STT.
3. **CONFIGURED THRESHOLDS HONORED:** Uses `config.voice.wake_threshold` (default 0.5), `config.voice.max_command_seconds`, and `config.resources.max_audio_command_seconds`. No conflicting hardcoded numbers.
4. **BOUNDED QUEUE & BACKPRESSURE:** Callback thread writes to `asyncio.Queue(maxsize=16)`. If the queue is full, oldest frames are dropped and a warning counter is incremented, preventing unbounded buffer growth.
5. **CLEAN MICROPHONE RELEASE:** When `always_listen=False` or during shutdown, `AudioSource.close()` terminates the stream and releases the microphone handle immediately.

## 15. Concurrency Model
Soundcard capture thread delivers PCM frames via `loop.call_soon_threadsafe(self._offer_frame, frame)`; consumer runs in event loop.

## 16. Cancellation Behavior
Stopping audio capture terminates hardware stream immediately, closes buffer, and cancels active recording tasks.

## 17. Timeout Behavior
Command recording capped at hard 30-second duration; trailing silence detected via VAD within 1.5 seconds.

## 18. Retry / Idempotency Behavior
Audio buffer read operations are single-consumer sequential; wake detection operates continuously across frame window.

## 19. Error Behavior
Soundcard dropouts or underruns trigger buffer reset and error state without crashing application daemon.

## 20. Security Invariants
Zero audio data transmitted over network prior to wake word detection boundary; ring buffer memory bounded.

## 21. Resource Limits
Frame duration 80 ms = 1280 samples = 2560 bytes at 16 kHz 16-bit mono PCM; max command audio 960,000 bytes.

## 22. Secrets / Privacy Behavior
Raw command audio retained only if `config.privacy.retain_audio` is enabled; zero persistent audio stored by default.

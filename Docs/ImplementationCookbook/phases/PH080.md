# Phase Packet: PH-080 — Local Voice Wake Pipeline

## 1. Purpose
Implement the local-first voice wake detection pipeline. Continuous microphone sampling is confined entirely to a local in-memory circular ring buffer (max 3s). Pre-wake audio is processed on-device by a single-threaded `openWakeWord` engine with **zero outbound network connectivity**. Post-wake command recording is initiated strictly after wake confirmation and terminated by VAD silence or timeout.

## 13. Exact Algorithms

### Algorithm: Continuous Wake Detection Loop
1. Initialize `AudioSource` with 16kHz, 16-bit mono PCM.
2. Initialize `WakeDetector` loading small custom wake model (e.g. `maya.onnx`).
3. While `state.is_listening`:
   a. Read 1280-byte audio frame (80ms).
   b. Write frame to `AudioRingBuffer` (drop oldest frame if buffer size > 96,000 bytes).
   c. Run `confidence = wake_detector.process_chunk(frame)`.
   d. If `confidence >= threshold` (default 0.70):
      i. Transition `AppState` to `WAKE_DETECTED`.
      ii. Break to command recording.

### Algorithm: Post-Wake Command Capture
1. Transition `AppState` to `RECORDING`.
2. Allocate command buffer initialized with last 500ms from ring buffer (to prevent clipped first word).
3. Loop until VAD detects 1.2s of continuous silence or total duration exceeds `10.0s`:
   a. Append new incoming audio frames to command buffer.
4. Stop recording. Return command audio bytes. Transition to `TRANSCRIBING`.

## 15. Concurrency Model
- Audio capture runs in an asynchronous worker thread feeding the asyncio event loop via an `asyncio.Queue`.

## 16. Cancellation Behavior
- Disabling "Always Listen" immediately cancels the capture worker and terminates ALSA/PulseAudio stream.

## 17. Timeout Behavior
- Hard 10.0s cap on command audio recording to prevent indefinite recording in noisy environments.

## 18. Retry/Idempotency Behavior
- Audio stream drops retry reconnection up to 3 times with exponential backoff before transitioning to `ERROR`.

## 19. Error Behavior
- Microphone device missing or permissions denied: Raises `AudioDeviceError`, transitions `AppState` to `ERROR`.

## 20. Security Invariants
- **Primary Enforcement:** Pre-wake audio strictly confined to memory-only circular buffer; **zero network sockets exist in `app/voice/wake.py`**.
- **Defense in Depth:** Disabling listening immediately frees audio buffers and terminates microphone stream.

## 21. Resource Limits
- Ring buffer capped at 96,000 bytes (3.0s PCM).
- openWakeWord restricted to 1 CPU thread.
- Resident memory budget for voice subsystem: <= 100 MiB.

## 22. Secrets/Privacy Behavior
- Pre-wake audio is never written to disk, never transcribed, and never sent across network.

## 23. Failure Cases
- Background noise causes false wake: VAD silence detection quickly terminates recording, returning empty audio.
- Audio input device unplugged: Catches device error, transitions to `ERROR`, logs warning, retries.

# Phase Packet: PH080 — Local Voice Wake Pipeline

## 1. Purpose
Implement the local-first voice wake detection pipeline. Continuous microphone sampling is confined entirely to a local in-memory circular ring buffer. Pre-wake audio is processed on-device by a single-threaded `openWakeWord` engine with **zero outbound network connectivity**. Post-wake command recording is initiated strictly after wake confirmation, producing a clean post-wake audio segment (`CommandAudioSegment`) terminated by VAD silence or configured timeout. Pre-wake ring buffer audio is NEVER prepended to command audio sent to cloud STT.

## 13. Exact Algorithms / Security Invariants
### Audio Frame Bridge & Concurrency
The microphone callback runs on an unmanaged OS audio thread. It MUST NOT invoke `queue.put_nowait` directly. It bridges to the event loop safely:
```python
class AudioFrameBridge:
    def __init__(self, *, queue_size: int = 16) -> None:
        self._loop: asyncio.AbstractEventLoop | None = None
        self._queue: asyncio.Queue[bytes] = asyncio.Queue(maxsize=queue_size)
        self.dropped_frames = 0

    def bind_running_loop(self) -> None:
        self._loop = asyncio.get_running_loop()

    def audio_callback(self, frame: bytes) -> None:
        loop = self._loop
        if loop is None or loop.is_closed():
            return
        loop.call_soon_threadsafe(self._offer_frame, bytes(frame))

    def _offer_frame(self, frame: bytes) -> None:
        if self._queue.full():
            try:
                self._queue.get_nowait()
            except asyncio.QueueEmpty:
                pass
            else:
                self.dropped_frames += 1
        try:
            self._queue.put_nowait(frame)
        except asyncio.QueueFull:
            self.dropped_frames += 1

    async def next_frame(self) -> bytes:
        return await self._queue.get()
```

### Clean Post-Wake Segmentation
- Audio captured prior to wake confirmation stays strictly in `AudioRingBuffer`.
- `CommandRecorder.record_command()` initiates capture only AFTER the wake boundary is triggered.
- Pre-wake ring buffer bytes are never prepended to `CommandAudioSegment.pcm_data`.

## 14. Reference Implementation / Capsule Guidance
See `Docs/ImplementationCookbook/17_REFERENCE_CODE_CAPSULES.md#Capsule-2` (`CAP-002`) for the bounded audio ring buffer implementation.

## 15. Concurrency Model
Soundcard capture thread delivers PCM frames via `loop.call_soon_threadsafe(self._offer_frame, frame)`; consumer runs in event loop.

## 16. Cancellation Behavior
Stopping audio capture terminates hardware stream immediately, closes buffer, and cancels active recording tasks.

## 17. Timeout Behavior
Command recording capped at hard 30-second duration; trailing silence detected via VAD within 1.5 seconds.

## 18. Retry / Idempotency Behavior
Audio buffer read operations are single-consumer sequential; wake detection operates continuously across frame window.

## 19. Error Behavior
Soundcard dropouts or underruns trigger buffer reset and error state without crashing application daemon.

## 20. Security Invariants
Zero audio data transmitted over network prior to wake word detection boundary; ring buffer memory bounded.

## 21. Resource Limits
Frame duration 80 ms = 1280 samples = 2560 bytes at 16 kHz 16-bit mono PCM; max command audio 960,000 bytes. Queue depth max 16 frames.

## 22. Secrets / Privacy Behavior
Zero audio data stored to disk by default; audio buffers freed from memory once command execution completes.

## 23. Failure Cases / Edge Cases
- Buffer overflow: Audio bridge drops oldest frames and increments `dropped_frames` counter under high CPU load.
- Silence timeout: Post-wake recording terminates when 1.5s of silence is detected, finalizing the segment.
- Hardware disconnect: Audio device read error triggers `AudioDeviceUnavailableError`; state machine enters `ERROR` state gracefully.
- Cancellation during recording: Hardware stream closed cleanly and partial segment discarded.
